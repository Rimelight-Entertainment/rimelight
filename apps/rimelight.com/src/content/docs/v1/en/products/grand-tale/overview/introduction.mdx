## What is Rimelight UI?

Rimelight UI is a component library for [Astro](https://astro.build), built on [UnoCSS](https://unocss.dev) and [CSSVariants](https://css-variants.vercel.app). It offers a suite of accessible and highly performant components both as native [Astro Components](https://docs.astro.build/basics/astro-components/) and [Vue Components](https://vuejs.org) for when complex client-side interactivity is necessary. It's the foundation of all our web applications and is available as an open source project for any to use.

## Core Technologies

Rimelight UI is built with performance and developer experience in mind, avoiding the bloat of traditional component libraries by leveraging a modern stack:

### UnoCSS

We use **UnoCSS** as our primary engine for atomic CSS. Unlike other frameworks, UnoCSS's on-demand, engine-first approach provides maximum performance and flexibility, generating only the CSS you actually use in milliseconds.

### CSS Variants

To manage component themes without the complexity of CSS-in-JS, we use `css-variants`. This allows us to define type-safe component variants (like `size` or `color`) and easily target sub-elements (slots) within complex components.

### Astro & Vue Integration

Rimelight UI is designed to work fluidly in mixed-framework environments. Our integration automatically registers Vue plugins and configures the virtual modules necessary for our global styling system to work across both Astro and Vue boundaries.

### Unplugin Icons

We use `unplugin-icons` to provide instant, zero-configuration access to thousands of open-source icons (primarily Lucide) directly as Vue or Astro components.

## Component Strategy

Rimelight UI provides two distinct versions of key components to give you total control over the hydration and rendering strategy of your application:

### Server-Rendered (Astro)

Components prefixed with **RLA** (e.g., `RLAButton`, `RLAHeader`) are native Astro components. They are optimized for server-side rendering and emit zero client-side JavaScript. Use these for structural layouts, static marketing sections, and anywhere interactivity isn't strictly required.

### Client-Hydrated (Vue)

Components prefixed with **RLV** (e.g., `RLVButton`, `RLVHeader`) are native Vue components. They are designed for high interactivity and client-side logic. You can drop these into an Astro page using standard hydration directives (like `client:load` or `client:idle`).

## Customization System

Rimelight UI uses a layer-cake override system that allows you to customize components at three different levels, from broadest to most specific:

### 1. Theme Definition

Each component defines its own theme in a `.theme.ts` file. This is where the component's default slots, base styles, variants, and default values are defined. This is the foundation that all customizations build upon.

For example, the Button component (`buttonTheme`) defines:

- **Slots**: The元素 that can be targeted (`root`)
- **Base styles**: Default classes applied to all instances
- **Variants**: Available options for `variant`, `color`, and `size`
- **Default values**: Which variant/color/size to use if not specified

### 2. Integration Config

When you configure `@rimelight/ui` in your `astro.config.ts`, you can provide global overrides that apply to all instances of a component across your entire application:

```typescript
// astro.config.ts
import { ui } from "@rimelight/ui"
import { defineConfig } from "astro/config"

export default defineConfig({
  integrations: [
    ui({
      components: {
        themes: {
          button: {
            defaultVariants: {
              variant: "solid",
              color: "primary",
              size: "md"
            }
          }
        }
      }
    })
  ]
})
```

This is useful for setting app-wide defaults without changing individual component usages.

### 3. Component Instance (`ui` prop)

On any individual component instance, you can provide a `ui` prop to override styles for that specific usage:

```astro
<RLAButton ui={{ root: "rounded-full" }}>
  Pill Button
</RLAButton>
```

The `ui` prop accepts an object where keys match the component's slots (like `root`, `leadingIcon`, etc.). These overrides are merged last and take highest precedence.

### Override Priority

The three layers merge in this order (later wins):

1. **Component theme defaults** (lowest priority)
2. **Integration config** from `astro.config.ts`
3. **`ui` prop on individual component** (highest priority)

This means you can set sensible app-wide defaults while still being able to override on a per-case basis.

## Frequently Asked Questions

<details>
  <summary>Is Rimelight UI free to use?</summary>
  Yes. Rimelight UI is a completely free and open source package under the [MIT
  License](https://opensource.org/license/mit).
</details>

<details>
  <summary>Can I use Rimelight UI without Astro?</summary>
  For the time being, no. The library is strictly distributed as an Astro integration, but in theory
  could be modularized enough to be usable as a Vite plugin, and we are open to contributions on
  this topic.
</details>

<details>
  <summary>Are other front-end frameworks supported?</summary>
  For the time being, no. The library currently only offers Astro and Vue components, but in theory
  could support other front-end frameworks, and we are open to contributions on this topic.
</details>

<details>
  <summary>Is Rimelight UI customizable?</summary>
  All components can have their styles overridden per slot and per variant, either globally or per
  instance, but their basic structure is fixed.
</details>

<details>
  <summary>Is Rimelight UI accessible?</summary>
  All components provide automatic ARIA attributes, keyboard navigation, focus management, and
  screen reader support. We offer an accessible foundation, but overrides and specific use cases
  might require additional accessibility considerations.
</details>
