---
title: Internationalization (i18n)
description: Multi-locale routing, translation loading, and the @rimelight/i18n integration.
---

The starter ships with a first-class internationalization (i18n) system built on the `@rimelight/i18n` package. It combines Astro's built-in i18n routing with a Cloudflare KV-backed translation loader for edge-fast locale delivery.

---

## How It Works

1. Astro's `i18n` config defines the supported locales and default locale.
2. All pages live under a `[locale]` dynamic segment (`src/pages/[locale]/`).
3. On first request, translation JSON is loaded from **Cloudflare KV** (production) or from the local JSON files (development).
4. The `rimelightI18n` Astro integration wires up the loader, injects helpers into the Astro global, and generates locale-aware routes.

---

## Supported Locales

Locales are configured in two places that must stay in sync:

**`src/config/i18n.config.ts`**

```ts
export const languages = ["en", "pt"]
```

**`astro.config.ts`**

```ts
i18n: {
  locales: ["en", "pt"],
  defaultLocale: "en",
  routing: "manual"
}
```

The `routing: "manual"` setting means Astro does not auto-redirect `/` → `/en/`. The redirect is handled by `src/pages/index.astro` which reads `Astro.currentLocale` (or falls back to the browser's `Accept-Language` header).

## Adding a New Locale

1. Add the locale code to both `i18n.config.ts` and the `locales` array in `astro.config.ts`.
2. Create `src/translations/<locale>.json` (copy `en.json` as a starting point).
3. Add the locale to the `rimelightI18n` integration call in `astro.config.ts`:

   ```ts
   import fr from "./src/translations/fr.json"

   rimelightI18n({
     translations: { en, pt, fr },
     kvBinding: "my-project_translations"
   })
   ```

4. Create a new KV namespace or add the locale to the existing one and upload the JSON:

   ```bash
   npx wrangler kv key put --namespace-id <id> "translations:fr" "$(cat src/translations/fr.json)"
   ```

## Translation Files

Translation files live at `src/translations/<locale>.json`. They are flat JSON objects where keys are dot-separated namespaces:

```json
{
  "nav.home": "Home",
  "nav.about": "About",
  "auth.signIn": "Sign in",
  "auth.signUp": "Create account"
}
```

Access translations in Astro components via the `t()` helper injected by the integration:

```astro
---
const t = Astro.locals.t
---
<h1>{t("nav.home")}</h1>
```

## The i18n Loader

`src/i18n/loader.ts` initialises the translation loader:

```ts
import { createTranslationLoader } from "@rimelight/i18n"
import en from "@/translations/en.json"
import pt from "@/translations/pt.json"

export default createTranslationLoader({ en, pt })
```

In production, the loader fetches the JSON blob from Cloudflare KV on the first request per locale and caches it in memory for the lifetime of the Worker isolate. In local development, it falls back directly to the imported JSON files.

---

## Locale Detection & Routing

The root `src/pages/index.astro` is responsible for redirecting to the correct locale:

```astro
---
return Astro.redirect(`/${Astro.currentLocale ?? "en"}/`)
---
```

All real pages live under `src/pages/[locale]/`. The `[locale]` segment is populated by Astro's i18n router and is always available as `Astro.currentLocale` inside any page.

---

## Sitemap Integration

The `@astrojs/sitemap` integration is configured to generate locale-qualified URLs:

```ts
sitemap({
  i18n: {
    defaultLocale: "en",
    locales: { en: "en-US", pt: "pt-BR" }
  }
})
```

This produces `<xhtml:link rel="alternate">` tags in the sitemap, which helps search engines discover all locale variants of each page.
