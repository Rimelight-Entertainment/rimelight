The rimelight.com websites use a internationalization system built on [@nanostores/i18n](https://github.com/nanostores/i18n) and the [astro-nanostores-i18n](https://github.com/cijiuge/astro-nanostores-i18n) integration.

## Architecture Overview

Translations are stored as flat JSON files under `src/translations/`. At build time these are bundled into the app as static imports. At runtime the `@rimelight/i18n` loader serves them via `astro-nanostores-i18n`.

```
┌──────────────────────────────────────────────────┐
│  src/translations/*.json                         │
│  ┌──────────────┐    ┌────────────────────────┐  │
│  │  en.json     │───▶│  @rimelight/i18n        │  │
│  │  es.json     │    │  createTranslationLoader│  │
│  │  pt.json     │    └───────────┬────────────┘  │
│  └──────────────┘                │               │
│                    ┌─────────────▼──────────────┐ │
│                    │  astro-nanostores-i18n      │ │
│                    │  useI18n() / t()            │ │
│                    └─────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

Cloudflare KV is available as an external store for cross-platform translation sharing, but the Astro app itself always reads from bundled JSON at runtime.

## Translation Files

Locale JSON files live in `src/translations/` and follow a flat-under-component naming convention:

```text
src/translations/
├── en.json      # Canonical source of truth
├── es.json      # Spanish (can be sparse)
└── pt.json      # Portuguese (can be sparse)
```

Keys within each component scope use underscores for hierarchy and hyphens for multi-word names:

```json
{
  "app_header": {
    "links_home_label": "Home",
    "links_blog_label": "Blog",
    "links_about_label": "About"
  },
  "page_home": {
    "section_hero_title": "Welcome",
    "section_hero_description": "This is the home page."
  }
}
```

Missing keys in non-default locales fall through to the base language automatically via `@nanostores/i18n`.

## Usage in Pages

Each localized page imports `useI18n` from `astro-nanostores-i18n:runtime` and provides fallback values for the keys it uses:

```astro
---
import { useI18n, currentLocale } from "astro-nanostores-i18n:runtime"

const activeLocale = Astro.currentLocale ?? "en"
currentLocale.set(activeLocale)

const messages = useI18n("page_home", {
  "section_hero_title": "Welcome",
  "section_hero_description": "This is the home page."
})
---

<h1>{messages["section_hero_title"]}</h1>
<p>{messages["section_hero_description"]}</p>
```

The fallback values serve as both the default text and the source of truth for the key name — they are the "code-first" English strings.

## The Loader

The `@rimelight/i18n` package provides `createTranslationLoader()`, which each app configures in its `src/i18n/loader.ts`:

```typescript
import { createTranslationLoader } from "@rimelight/i18n"
import en from "../translations/en.json"
import es from "../translations/es.json"
import pt from "../translations/pt.json"

export default createTranslationLoader({ en, es, pt })
```

The loader is purely static — it maps locale + component name to the bundled JSON data. No runtime imports or Cloudflare-specific code.

This loader is wired into the Astro config via `astro-nanostores-i18n`:

```typescript
import nanostoresI18n from "astro-nanostores-i18n"

export default defineConfig({
  integrations: [
    nanostoresI18n({
      translationLoader: "./src/i18n/loader.ts",
      addMiddleware: true,
      translations: {
        "en": en,
        "es": es,
        "pt-br": pt
      }
    })
  ]
})
```

## Cloudflare KV

<RLACallout color="warning" variant="soft">
  KV runtime hydration in the translation loader is not yet implemented. The information below
  describes the intended architecture. Currently KV is only accessible through the API routes
  described below.
</RLACallout>

Cloudflare KV can be used as an external translation store for projects that share translations across multiple platforms (web, native apps, games). KV is populated via API endpoints and consumed by external services, not by the Astro page loader.

### Adding KV

Add `TRANSLATIONS_KV` to `wrangler.jsonc`:

```jsonc
{
  "kv_namespaces": [
    {
      "binding": "TRANSLATIONS_KV",
      "id": "your-namespace-id"
    }
  ]
}
```

### Seeding KV

A `POST /api/i18n-test/seed` endpoint reads the bundled JSON files and writes each component's translations to KV under keys like `locale:en:app_header`. This is useful for bootstrapping KV from the canonical JSON source.

### Reading KV

A `GET /api/i18n-test/status` endpoint checks whether the KV binding is present and reachable.

KV-stored translations are not automatically read by the page loader. The architecture is designed so that a future `withKVFallback()` wrapper can be added without changing the static loader or any application code.
