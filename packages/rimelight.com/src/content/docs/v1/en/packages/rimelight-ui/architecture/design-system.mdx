## UnoCSS

Rimelight UI uses internally a UnoCSS preset that includes and extends UnoCSS presets [Wind4](https://unocss.dev/presets/wind4) and [Typography](https://unocss.dev/presets/typography). your project by adding additional UnoCSS presets, rules, or theme tokens as according to their [documentation](https://unocss.dev/guide/).

Exports

- The preset is exported by the library and can be imported from `@rimelight/ui/presets`.
- You can also import individual parts if needed, for example `@rimelight/ui/presets` (default export).

## UnoCSS & Engine-First Design

Unlike traditional component libraries that rely on pre-built CSS or complex runtime JavaScript, Rimelight UI uses an **engine-first** approach powered by **UnoCSS**.

This means our design system is defined through rules and shortcuts that generate atomic CSS on-demand. This leads to significantly smaller bundles and faster builds.

## Colors

Rimelight UI's color system is built around semantic aliases that describe the **purpose** of the color. This allows us to maintain a consistent visual language even if the underlying color palette changes.

### Default Color Mappings

| Color       | Purpose                                            | Default Tint |
| :---------- | :------------------------------------------------- | :----------- |
| `primary`   | Main CTAs, brand identity, active states.          | `green`      |
| `secondary` | Complementary actions, less prominent UI elements. | `blue`       |
| `info`      | Informational messages, neutral notifications.     | `blue`       |
| `success`   | Positive feedback, completions, active indicators. | `green`      |
| `warning`   | Cautions, pending states, attention-needed items.  | `yellow`     |
| `error`     | Errors, validation failures, destructive actions.  | `red`        |
| `neutral`   | Text, backgrounds, borders, disabled states.       | `slate`      |

### Rimelight Brand Colors

In addition to the semantic colors, Rimelight UI defines brand-specific colors:

| Color        | Purpose                                 | Default Tint |
| :----------- | :-------------------------------------- | :----------- |
| `commentary` | Comments, feedback, discussions.        | `violet`     |
| `ideation`   | Brainstorming, ideas, creative input.   | `amber`      |
| `source`     | Source code, editor, technical content. | `cyan`       |

### Using Semantic Colors

You can use these semantic names directly in component props:

```astro
<RLAButton color="primary">Primary Action</RLAButton>
<RLAButton color="error" variant="outlined">Delete</RLAButton>
```

Or as UnoCSS utility classes:

```html
<div class="text-primary-500 bg-neutral-100 p-4">Styled content</div>
```

## Customizing Colors

You can override the default color mappings or add custom colors via the integration configuration:

```typescript
// astro.config.ts
import { ui } from "@rimelight/ui"
import { defineConfig } from "astro/config"

export default defineConfig({
  integrations: [
    ui({
      colors: {
        // Override existing colors
        primary: "emerald",
        secondary: "violet",

        // Add custom colors
        brand: "orange",
        accent: "pink"
      }
    })
  ]
})
```

When you change a color mapping, all components using that semantic color will automatically use the new palette. For example, setting `primary: "emerald"` will make all buttons with `color="primary"` use emerald instead of green.

### Available Color Palettes

Rimelight UI supports any color from the Tailwind CSS palette. Some popular options include:

- **Neutrals**: `slate`, `gray`, `zinc`, `neutral`
- **Warm**: `orange`, `amber`, `yellow`, `lime`
- **Cool**: `green`, `emerald`, `teal`, `cyan`
- **Primary**: `blue`, `indigo`, `violet`, `purple`
- **Accent**: `fuchsia`, `pink`, `rose`, `red`

For a complete list, see the [Tailwind CSS Colors](https://tailwindcss.com/docs/colors) documentation.

## Typography

Rimelight UI uses a modern typography system that prioritizes legibility and hierarchy.

- **Sans-serif (UI):** We prefer system-ui fonts for native feeling and performance.
- **Monospaced (Code):** We use JetBrains Mono for all code-related content.

## CSS Variable Generation

When you configure custom colors, Rimelight UI generates CSS variables at build time that components use. The generated variables follow this pattern:

```css
/* Generated from: colors: { primary: "emerald" } */
@theme {
  --color-primary-50: #ecfdf5;
  --color-primary-100: #d1fae5;
  /* ... all shades 50-950 */
  --color-primary-foreground: #022c22; /* darkest shade for text */
  --color-primary-muted: #f0fdf4; /* lightest shade */
}
```

Components use these variables through UnoCSS utility classes like `bg-primary-500` or `text-primary-foreground`.

  enabling components to use the appropriate shade for any state (hover, focus, subtle backgrounds,
  etc.).
</RLACallout>

Rimelight UI is designed to be a flexible and powerful bridge between different web technologies. This page explains the core architectural decisions and mechanisms that power the library.

## The Astro Integration

The primary entry point is the `ui()` function, which returns an array of Astro integrations. It handles the orchestration of:

- **Vue Support**: Automatically includes `@astrojs/vue`.
- **UnoCSS**: Sets up UnoCSS for high-performance atomic CSS generation. UnoCSS is our primary styling engine, providing a more performant and flexible alternative to traditional atomic CSS frameworks.

## Virtual Configuration System

To allow components to access global UI configuration without complex prop drilling, Rimelight UI uses a **Vite virtual module**.

1. When the integration starts, it merges the user's `ui` overrides with the `defaultUIConfig` using a custom recursive merge utility.
2. It creates a virtual module named `virtual:rimelight-ui`.
3. This module exports a `getUIConfig()` function that returns the merged configuration.

Components can then import and use this config:

```typescript
import { getUIConfig } from "virtual:rimelight-ui"
const config = getUIConfig()
```

## Styling and Themes

Styles in Rimelight UI are managed through a powerful combination of **UnoCSS** and **CSS Variants**.

### CSS Variants (`css-variants`)

Each component has a corresponding `.theme.ts` file in `src/themes/` (e.g., `button.theme.ts`). These files define the component's structure and appearance using the [**css-variants**](https://github.com/marcelocfilho/css-variants) library.

This approach provides:

- **Type-Safe Variants**: Define variants like `size` (xs to xl), `color` (primary, secondary, info, etc.), and `variant` (solid, outlined, ghost) with full TypeScript support.
- **Slot-Based Styling**: Target specific sub-elements within a component. For instance, the Button component defines a `root` slot.
- **Atomic Classes**: Use UnoCSS atomic classes directly within the theme definitions (e.g., `inline-flex`, `items-center`, `gap-4xs`).

Here is a simplified example of how themes are structured:

```typescript
export const buttonTheme = {
  slots: ["root"],
  base: {
    root: ["inline-flex items-center justify-center transition-all"]
  },
  variants: {
    variant: {
      solid: { root: "shadow-xs" },
      ghost: { root: "hover:bg-primary/10" }
    },
    size: {
      md: { root: "h-9 px-sm text-sm" }
    }
  },
  defaultVariants: {
    variant: "solid",
    size: "md"
  }
}
```

## Style Overrides with the `:ui` Prop

One of the most powerful features of Rimelight UI is the ability to override component styles at multiple levels. The `:ui` prop allows you to target specific "slots" (elements) within a component.

We use a smart merging strategy powered by a custom recursive merge utility to combine overrides across three distinct layers, with each subsequent layer taking priority:

1. **Layer 1: Component Theme**
   The baseline styles and variants defined in the component's `.theme.ts` file. These are the "factory defaults."

2. **Layer 2: Integration Config (Global)**
   Overrides provided in the `ui()` integration in your `astro.config.ts`. These apply to every instance of the component across your entire site.

```typescript
ui({
  components: {
    themes: {
      button: {
        // Override defaults or apply to all buttons globally
        defaultVariants: { size: "lg" },
        slots: {
          root: "rounded-full px-8"
        }
      }
    }
  }
})
```

3. **Layer 3: Component Prop (Local)**
   The `:ui` prop provided directly to a component instance. This has the highest priority and is used for one-off overrides.

```astro
<RLAButton ui={{ root: 'bg-primary-600' }}>
  Instance Specific Styling
</RLAButton>
```

When a component (such as `RLAButton.astro`) renders, it resolves these layers in the following order:

1. It fetches the global configuration (Layer 2) from the `virtual:rimelight-ui` module.
2. It uses the recursive merge utility to merge the local `:ui` prop (Layer 3) with the fetched global configuration.
3. It passes the active variant props (e.g., `color="primary"`) to the `css-variants` engine to generate the base classes (Layer 1).
4. Finally, it uses a class merging utility to combine the base variant classes with the merged overrides, resolving conflicts so that higher-priority layers (like local overrides) win (e.g., overriding `px-4` with `px-8`).
