`@rimelight/i18n` provides clean, simple translation helpers designed to eliminate boilerplate in Astro components and pages.

## Direct String Lookups with `t()`

The `t()` helper is the recommended way to resolve translations directly from your `src/translations/` JSON files using dot-notation (`component.key`).

### Basic Usage

```astro
---
import { t } from "@rimelight/i18n"
---

<h1>{t("page_home.section_hero_title")}</h1>
<p>{t("page_home.section_hero_description")}</p>
```

### Parameter Interpolation

Pass an optional parameters object to replace `{variable}` placeholders in your translation strings:

```json
// src/translations/en.json
{
  "page_home": {
    "welcome": "Welcome back, {name}!"
  }
}
```

```astro
---
import { t } from "@rimelight/i18n"
---

<p>{t("page_home.welcome", { name: "Developer" })}</p>
```

### Explicit Astro Context (Optional)

If needed during complex SSR page loads, you can optionally pass `Astro` as the first parameter:

```astro
---
import { t } from "@rimelight/i18n"

const title = t(Astro, "page_home.section_hero_title")
---
```

## Component Map Lookup with `useI18n()`

If you prefer retrieving all translation keys for a specific component section as an object map, use `useI18n()`.

```astro
---
import { useI18n } from "@rimelight/i18n"

// Resolves all keys defined under "page_home" in en.json / pt.json
const m = useI18n("page_home")
---

<h1>{m.section_hero_title}</h1>
<p>{m.section_hero_description}</p>
```

## Active Locale Helper `getLocale()`

Retrieve the current request's active locale code without accessing `Astro.currentLocale` manually:

```astro
---
import { getLocale } from "@rimelight/i18n"

const activeLocale = getLocale() // returns "en", "pt", etc.
---
```

---

## Locale-Aware Routing with `getRelativeLocaleUrl()`

Generate relative URLs prefixed with the current active locale automatically:

```astro
---
import { getRelativeLocaleUrl } from "@rimelight/i18n"
---

<!-- Automatically prefixes with current request locale -->
<a href={getRelativeLocaleUrl("/blog")}>Blog</a>

<!-- Force prefixing for a specific target locale -->
<a href={getRelativeLocaleUrl("pt", "/blog")}>Blog (Português)</a>
```

---

## Automatic Fallbacks & Region Codes

Lookups automatically fall back gracefully across region-specific codes:

1. Exact locale match (e.g. `pt-BR`)
2. Base language match (e.g. `pt`)
3. Configured default locale (e.g. `en`)
4. Raw key string if key is not found
