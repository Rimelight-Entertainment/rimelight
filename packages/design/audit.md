# Design parity audit: web, Rust Space, Media (merged proposal)

Date: 2026-11-22. Status: proposal for owner review. Nothing was built, committed or changed in any repo.

**Sources.** W = `packages/design/audit/web.md` (SolidJS `@rimelight/ui`). S = `packages/design/audit/rust-space.md` (Space `rimelight_ui`). M = `packages/design/audit/media.md` (Rimelight Media Slint). P = `rimelight-space/docs/plan.md` section 3.1 (decisions D1 to D8). A letter and number, for example S:83, is a line of that file.

**Method.** L = light theme, D = dark theme. "Nearest" gives the web ramp shade closest to a Space or Media value, with its sRGB Euclidean distance d. The distance was computed for this document from the ramp tables at W:17-191. It is not perceptual and was not checked on screen.

## 1. Summary

- Space's values are the proposed shared values wherever Space has one (P:D4, P:D6). Web and Media move to them, except for the owner choices in section 6.
- Space and Media agree on most colour roles. They differ on surface-sunken light (S:83 #F3F9FF, M:24 #E8EDF3). Media has surface-hover and surface-pressed (M:26-27), which Space lacks.
- Web neutrals have chroma 0 (W:19-29), and Space's neutrals are tinted (S:86-91). Space's success, info and warning hues sit 24 to 77 away from the nearest web shade (section 2.1).
- Most chromatic web shades are out of sRGB gamut (W:37-155), so the generator must gamut-map.
- Controls: sm, md and lg keep Space (28, 34, 40 px). xs takes the web-derived 22 px. xl is 48 px, because the web-derived 32 to 34 px would sit below Space's lg.
- Type: all nine Space styles (S:341-349) are shared. Media's heading and title sizes (M:82-83) and its Segoe UI family (M:78) change.
- Reduced motion and text scale exist as Space tokens but are not wired (S:519, S:521). Easing tokens are not emitted to Slint (S:318).
- Commentary, ideation, source and secondary have no Rust roles yet (section 3). P:D5 asks for all ten palettes.
- Section 5 lists findings to fix whatever the parity choices.
- Section 6 lists the open questions for the owner.

## 5. Findings to fix regardless of parity

1. **Web ramps are out of sRGB gamut.** Most chromatic shades are clipped in one or both themes. Examples: primary 200 light (W:39), error 500 light and dark (W:132), commentary 500 (W:150). The generator must gamut-map (W:3-6 notes that hexes are clipped approximations).
2. **Web neutrals have chroma 0.** Neutral shades are all `0.000` chroma (W:19-29). Space's neutrals are cool (S:86, S:89-91). This is a hue drift, not a lightness drift.
3. **Reduced motion is not wired in Space.** The setter and resolver are only called by the gallery harness and tests (S:519, citing `apps/gallery/src/harness.rs:184`). `tokens.slint:15` says the OS setting is not readable from Slint. The app always animates. Media has no reduced-motion token (M:98). The web has a global rule (W:441).
4. **Text scale is not wired in Space.** Only the gallery sets it (S:521). Control heights use `zoom-factor` only, so they do not grow with text (S:522). Not verified visually (S:522).
5. **Easing tokens are not emitted to Slint.** `EASE_STANDARD` and `EASE_ENTER` exist (S:315-316). Slint hard-codes `ease-in-out` (`switch.slint:112`, `progress.slint:39`, `skeleton.slint:27`), `ease-out` (`app-shell.slint:2572, 2600`, `sheet.slint:190`) and `linear` (`spinner.slint:39`) (S:318).
6. **A file named in the codegen comment does not exist.** `codegen.rs:279` says easings are in `ui/motion.slint`, and that file is missing (S:320, S:534).
7. **The resting input and select outline uses an exempt token.** `input.slint:144` and `select.slint:355` draw `border-subtle` at rest, which is exempt (`contrast.rs:22`). Only the hover token `border-strong` is checked (`contrast.rs:318`) (S:192).
8. **Badge and tag fills with on-accent ink are not checked.** `badge.slint:13-22` draws tone fills with `text-on-accent` ink. No checked pair covers these (S:193).
9. **Avatar initials are not checked.** `avatar.slint:32` and `:41`. The comment at `avatar.slint:3-6` quotes ratios, but no pair in `checked_pairs` covers them (S:194).
10. **The menu row highlight is covered only through ghost button pairs.** `menu.slint:126-127` (S:195).
11. **Menu rows have no drawn keyboard focus ring.** The highlight tint is the only indicator (S:506, `menu.slint:209-210`).
12. **Web heights are derived, not measured.** W:5 states it; W:242 and W:506 repeat it. The brief requires measuring from rendered CSS (P:ST1.1).
13. **Media uses colour literals in place of tokens.** 95 literal lines outside `tokens.slint` (M:293-361). Examples: `state.slint:139` record red (M:352), `widgets.slint:273` amber range (M:358), `image_page.slint:324` twelve swatches (M:326).
14. **Media surface-sunken light differs from Space.** M:24 is #E8EDF3, S:83 is #F3F9FF (M:108).
15. **Media control height differs from Space.** M:70 gives 32 px; S:251 gives 34 px (M:102).
16. **Media icon-large differs from Space.** M:76 gives 28 px; S:271 gives 24 px (M:101).
17. **Media heading and title differ from Space.** M:82-83 gives 20 and 28 px; S:342-343 give 26 and 22 px (M:93-94).
18. **Media font is the Windows UI face.** M:78 and M:89 give Segoe UI Variable Text, against P:D6. Media also uses literal Segoe UI and Consolas in the text page (M:384-385).
19. **Space has no hover token for the danger button.** Hover keeps the fill (S:243, `component.rs:104`).
20. **Two Space component aliases have no consumer.** `tab` and `table_row` (S:243, S:533) are unused as far as the audit found.
21. **Web controls use radius 6, Space controls use 5.** W:409 (`rounded-md`) against S:300 (`radius-control`). Also M:56 uses 5.
22. **Web scrim is opaque.** `scrim` is `#000000` with no alpha (W:11). Space and Media use alpha (S:119, M:48).
23. **Web font families are not verified.** `fontsource` family names were not checked on render (W:234, W:509).
24. **Media has no surface-hover or surface-pressed in Space.** Every Media hover and pressed state depends on them (M:99).
